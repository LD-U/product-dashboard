# Product → Sales & Customer Experience Dashboard Framework

A strong cross-functional dashboard helps Sales and Customer Experience teams:

- Understand what’s shipping and why
- Communicate confidently with customers
- Prepare for objections and questions
- Identify upsell/retention opportunities
- Set expectations accurately
- Align messaging across teams

The best dashboards are not just release logs. They provide context, customer impact, readiness guidance, and forward visibility.

---

# Recommended Dashboard Structure

## 1. Executive Product Snapshot

This section gives GTM teams a fast, high-level understanding of product momentum and priorities.

### Include

| Component | Purpose |
|---|---|
| Quarterly product themes | Reinforces strategic direction |
| Current company/product priorities | Aligns messaging with roadmap focus |
| What’s improving most for customers | Helps Sales position value |
| Key product metrics | Demonstrates traction and adoption |
| Top customer problems being solved | Creates alignment with CX conversations |

### Example

- Q3 Focus Areas:
  - Automation & efficiency
  - Reporting improvements
  - Enterprise permissions
- Goal:
  - Reduce onboarding friction
  - Increase multi-location adoption
  - Improve workflow completion speed

# 2. Recently Released Features

This is typically the most heavily used section.

The goal is not only to announce features, but to help customer-facing teams explain value.

## Recommended Release Card Format

Each feature should include:

| Field | Why It Matters |
|---|---|
| Feature name | Easy reference |
| Release date | Timing awareness |
| Status | GA, Beta, Early Access, Internal Only |
| Customer problem solved | Helps storytelling |
| Ideal customer/use case | Supports qualification |
| Business impact | Retention, efficiency, reporting, etc. |
| Key talking points | Enables Sales/CX consistency |
| Screenshots/GIFs | Fast comprehension |
| Documentation link | Self-service learning |
| Limitations/known gaps | Prevents overselling |
| Pricing/package impact | Important for Sales |
| Competitive positioning | Helpful for objections |

---

# 3. Work In Flight (Currently In Development)

This section builds transparency and reduces surprise.

The key is balancing visibility with expectation management.

## Recommended Categories

| Status | Meaning |
|---|---|
| Discovery | Research/problem validation |
| Planned | Approved but not started |
| In Progress | Active development |
| Internal QA | Nearing release |
| Beta | Limited customer rollout |
| Launching Soon | GTM preparation needed |

---

## For Each Initiative Include

| Component | Purpose |
|---|---|
| Initiative name | Reference point |
| Problem being solved | Helps contextualize work |
| Target customer segment | Supports pipeline/customer targeting |
| Expected customer impact | Helps CX planning |
| Estimated timing window | Expectation management |
| Confidence level | Prevents roadmap overcommitment |
| Dependencies/risks | Adds realism |
| Internal owner/team | Escalation path |
| GTM readiness needs | Training, collateral, pricing updates |

---

## Important Guidance

Avoid exact dates unless confidence is high.

Better framing:

- Targeting late Q3
- Expected this half
- Beta planned next quarter
- Exploring for future roadmap

This prevents Sales from accidentally making contractual promises.

# Most Important Principles

## 1. Translate Features Into Customer Outcomes

Avoid:

> “Added configurable workflow automation.”

Prefer:

> “Reduces manual processing time for multi-location operators by automating repetitive intake tasks.”

---

## 2. Separate Commitments From Exploration

Clearly distinguish:

- Exploring
- Planned
- In development
- Committed
- Released

This protects trust with customers.

---

## 3. Optimize for Fast Consumption

Customer-facing teams are busy.

Use:

- Short summaries
- Visual indicators
- Tags
- GIFs/screenshots
- “Why it matters” callouts
- Search/filter functionality

---

## 4. Make It Actionable

Every section should answer:

- What should Sales do?
- What should CX communicate?
- Which customers matter most?
- What risks should teams know?

# Example “Perfect” Feature Update

## Smart Intake Automation

### Status
GA — Released Aug 12

### Problem Solved
Customers manually categorize thousands of incoming inventory items.

### Customer Impact
Reduces intake processing time by ~40% for high-volume operators.

### Best Fit Customers
- Multi-location organizations
- High-volume intake workflows
- Teams with centralized processing

### Key Talking Points
- Faster throughput
- Reduced human error
- Improved reporting consistency
- Minimal onboarding required

### Known Limitations
- Does not yet support custom category logic
- API-triggered workflows coming later

### CX Guidance
Recommend rollout during low-volume periods.

### Sales Opportunity
Strong expansion conversation for enterprise operations teams.

### Resources
- Demo video
- Help center article
- Setup checklist
- FAQ

# Ideal Outcome

The dashboard should make Sales and CX teams feel:

- Informed
- Prepared
- Confident
- Aligned with Product
- Equipped to communicate customer value
- Aware of risks and limitations
- Able to proactively drive adoption and expansion

The strongest dashboards create organizational alignment — not just awareness.
